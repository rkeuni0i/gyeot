# 곁 — 상담실 곁의 사안처리 동료

이산중학교 사안처리·상담 도우미(테스트용 챗봇). 가제 MindGuide에서 이름을 바꿨습니다(2026-10-19). 프로젝트 폴더는 `gyeot`(2026-10-19 `mindGuide_test`에서 이름 변경)이고, 저장소 파일 `index/mindguide.db`와 환경변수 `MINDGUIDE_MODEL`은 그대로 씁니다. 로고(서로 기댄 잎 두 장)는 `docs/brand/`에 있고 `python docs/brand/make_logo.py`로 다시 만듭니다.

학교에 혼자 근무하는 상담사가 **절차·기한·법적 의무·학교 규정·양식·기관 연계**를 빠르게 확인하도록 돕는 챗봇입니다.
**이산중학교(경기) 전용** 챗봇입니다(Wee 클래스 운영, 전문상담교사 1명 배정 — 학교 홈페이지에서 확인). 근거 자료는 두 개이고 **이산중 규정을 먼저** 확인합니다. 답변의 사실 문장마다 `[이산중 p.쪽]` 또는 `[가이드북 p.쪽]` 근거를 답니다.

| 인용 이름 | 파일 | 역할 |
|---|---|---|
| 가이드북 | `data/2026학년도 학교폭력 사안처리 가이드북.pdf` (216쪽) | 전국 공통 학교폭력 사안처리 절차(법령·교육부) |
| 이산중 | `data/이산중학교 학생생활규정(2026.8.27 개정).pdf` (22쪽) | 이 학교의 생활지도·상담·학생생활교육위원회·징계·출결 규정 |
| 사이버상담 | `data/2023_사이버 비행 청소년 상담개입 매뉴얼(한국청소년상담복지개발원).pdf` (100쪽) | 사이버폭력 가해(사이버 비행) 청소년 개인상담 단계·활동 |
| 디지털상담 | `data/2024_디지털 미디어 위기 청소년 유형 및 개입 매뉴얼(한국청소년상담복지개발원).pdf` (134쪽) | 디지털 미디어 폭력 피해·가해, 과의존, 온라인 위험행동 개입 |

- 질문 유형 라우팅: 질문을 먼저 아래 유형으로 나누고, 유형마다 확인 순서·검색 몫·답변 형식을 다르게 씁니다(`rag.py`의 `QTYPES`). 유형 판단은 검색어 생성과 같은 Gemini 호출에서 함께 해서 추가 호출이 없습니다. 화면 답변 위에 "🔎 질문 유형 · 확인 순서"가 표시됩니다.

  | 유형 | 확인 순서 | 답변 형식 |
  |---|---|---|
  | 학교 맞춤형 | 이산중 → 가이드북 → 매뉴얼 | 이산중 규정 → 지금 해야 할 일 |
  | 학교폭력 절차·법 | 가이드북 → 이산중 → 매뉴얼 | 사실은 바로, 상황은 법정 절차 순서 |
  | 용어·개념 정의 | 가이드북 → 사이버상담 → 디지털상담 → 이산중 | 법적 정의 → 매뉴얼 정의·유형 → 비슷한 용어 차이 |
  | 상담 가이드 | 사이버상담 → 디지털상담 → 가이드북 → 이산중 | 상담 개입 참고(단계·활동) + 절차를 함께 물으면 지금 해야 할 일 |
  | 학생 눈높이 설명 | 사이버상담 → 디지털상담 → 가이드북 → 이산중 | 한 줄 설명·비유·예시·꼭 알려줄 점(학생 말투, 줄마다 근거) |
  | 위기(자해·자살) | 이산중 → 가이드북 → 매뉴얼 | 자료에 없음을 밝히고 Wee센터·1388 연계 |
- 답변은 "## 이산중학교 규정"부터 쓰고, 관련 조항이 없으면 "이산중 규정에는 관련 조항이 없어 가이드북 기준으로 안내합니다"라고 밝힌 뒤 가이드북으로 답합니다.
- 학교폭력 사안은 법정 절차라 가이드북 절차를 함께 안내하고, 학교폭력이 아닌 생활지도 위반은 이산중 학생생활교육규정을 따릅니다. 두 자료가 다르면 법령이 우선임을 밝힙니다.
- 근거 표는 문서 구분 없이 벡터 유사도(코사인) 높은 순으로 보여줍니다.
- 문서와 학교 설정은 `rag.py`의 `DOCS`, `SCHOOL_NAME`에 있습니다. 다른 학교로 바꾸려면 PDF를 `data/`에 넣고 이 두 값을 고친 뒤 `build_index.py`를 다시 실행합니다.

상담 기법·공감·정서 개입은 다루지 않습니다(상담사의 몫).

## 실행

1. `run.bat` 더블클릭
2. 브라우저에서 http://localhost:8501 이 열림 (안 열리면 주소를 직접 입력)

직접 실행할 때:

```
C:\Users\2003g\anaconda3\envs\DS\python.exe -m streamlit run app.py
```

- 의존성 설치: `pip install -r requirements.txt` (Python 3.10+ 권장)
- API 키: Windows 환경변수 `GEMINI_API_KEY` 또는 프로젝트 루트의 `.env` 파일에서 읽습니다. (`.env.example` 참고)
- 모델: `gemini-3.8-flash` (환경변수 또는 `.env`의 `MINDGUIDE_MODEL`로 바꿀 수 있음)

## 동작 방식

```
질문 ─▶ ① 질문 정리·검색어 생성(Gemini) ─▶ ② 하이브리드 검색 ─▶ ③ 답변 생성(Gemini) ─▶ 화면
         후속 질문일 때만 이전 질문 반영      벡터(Gemini 임베딩 코사인)      자료 안에서만 답하고
         가이드북 용어 검색어 2~5개           + BM25(형태소) → RRF 합산       [p.쪽] 인용
```

- 인덱스: 4개 문서 → 쪽 단위 청크 696개(가이드북 313, 이산중 59, 사이버상담 141, 디지털상담 183)
  - 저장소 `index/mindguide.db`(SQLite): 문서·층·주제·질문 유형·청크(본문·형태소·`gemini-embedding-001` 3072차원 임베딩)·평가 기록·알림. 자세한 구조는 [docs/DB_설계.md](docs/DB_설계.md)
- 검색(v8): 문서별로 따로 찾아 합칩니다. ① 이산중 규정: 원 질문 6 + 검색어별 3(최대 12청크) ② 가이드북: 원 질문 8 + 검색어별 5(최대 24청크), 검색된 본문이 `<양식2-4>`처럼 부록 양식을 가리키면 그 양식 앞 2쪽을 함께 넣음(최대 3개 양식) ③ 상담 매뉴얼: 문서마다 원 질문 4 + 검색어별 2(최대 7청크). 가이드북 부록3(법령 원문)·매뉴얼 연구방법·참고문헌은 순위를 낮췄습니다. 설정은 `rag.py`의 `RETRIEVAL`.
- 답변 형식: 정의·요건·기한 같은 사실 질문은 바로 답하고, 상황 질문은 "지금 해야 할 일 / 연계 기관 / 유의사항 / 양식" 구성으로 답합니다.
- 성폭력 관련 단어가 있으면 "수사기관 즉시 신고 의무"를 먼저, 자해·자살 단어가 있으면 "이 가이드북은 자해·자살 대응을 다루지 않음"을 먼저 안내합니다.

## 자료 관리(추가·사용 중지·완전 삭제·정기 점검)

사이드바에서 **📚 자료 관리**를 고르면 세 메뉴가 있습니다. 자료는 모두 SQLite 저장소 `index/mindguide.db`에 있고, 설계는 [docs/DB_설계.md](docs/DB_설계.md)에 정리했습니다.

**📥 자료 추가**
1. PDF 업로드(같은 PDF가 이미 있으면 파일 해시로 막음) → **AI 평가 실행**
2. `doc_agent/agent.py`가 12개 기준(`doc_agent/criteria.json`)으로 판단: 자동 측정 + Gemini 판단(기준마다 0/1/2점과 근거 쪽) + 코드로 최종 판정(필수 기준 0점 또는 55% 미만 → 비추천, 75% 이상이고 0점 없음 → 추천, 그 사이 → 조건부)
3. 상담사가 인용 이름·정식 이름·층(공통/주제/학교)·주제·질문 유형을 확인하고 승인(조건부는 주의 확인, 비추천은 사유 입력)
4. `doc_agent/ingest.py`가 한 트랜잭션으로 등록하고 그 자료 청크만 임베딩해 저장. 평가의 주의할 점은 '사용 전 알림'으로 남음

**🗂️ 등록 자료**: 자료별 상태·층·주제·청크 수·최근 판정·알림 수·다음 점검일. 자료를 골라
- **사용 중지 / 다시 사용**: 검색에서만 빼기(기본 자료도 가능)
- **지금 다시 평가**
- **완전 삭제**(확인 체크 필요): 저장소의 자료·청크·평가 기록·알림과 `data/`·`doc_agent/inbox/`의 PDF를 지움. 기본 4개 자료는 사용 중지만 가능

**🔔 알림·정기 점검**: 마지막·다음 점검일, 지금 점검 실행, 확인하지 않은 알림 목록과 "확인함"

### 학기별 정기 점검과 사용 전 알림
- 182일(한 학기)마다 모든 활성 자료를 다시 평가해(오늘 날짜 기준 최신성, 법령 시행일 비교, 직전 평가 대비 하락 등) 알림을 만듭니다(🔴 긴급 / 🟠 주의 / 🔵 참고).
- **앱을 열 때 점검 시기가 지났으면 자동으로 백그라운드 점검**을 시작합니다.
- 앱을 열지 않아도 점검하려면 `run_review.bat`을 Windows 작업 스케줄러에 등록합니다(시기가 아니면 바로 끝남). 예: 매주 월요일 9시에 확인

```
schtasks /Create /TN "곁 정기 점검" /TR "C:\Users\2003g\Documents\Project_sesac\gyeot\run_review.bat" /SC WEEKLY /D MON /ST 09:00
```

- 알림은 챗봇 사이드바("🔔 자료 유의사항 N건")와, 답변이 인용한 자료에 주의·긴급 알림이 있을 때 답변 바로 아래 "사용 전 확인" 상자로 보입니다.
- 명령줄: `python doc_agent\periodic_review.py [--force]`, 평가만: `python doc_agent\agent.py "PDF 경로"`

## 화면에서 확인할 것

- **근거 표**(답변 바로 아래): 순위, PDF 쪽, 인용 여부(✅), 벡터 유사도(코사인), BM25 점수, 각 순위, 장 이름
- **근거 원문 보기**: 검색에 쓴 질문, 생성된 검색어, 청크 원문, 매칭된 검색어, 원본 쪽 이미지
- 검색되지 않은 쪽을 인용하면 노란 경고가 뜹니다.

가이드북을 처음 검토한 요약은 `docs/가이드북_검토_요약.md`에 있습니다.

| `ui_style.py` | 화면 공통 스타일(Figma 시안: 연두 바탕·흰 사이드바·알약 메뉴, 고른 메뉴·지금 단계는 더 진한 연두) |

| `build_index.py` | 청크가 없는 자료의 청크를 PDF에서 만들고 임베딩(`--all`이나 doc_id로 다시 만들기). 저장소가 없으면 먼저 만듦 |
| `run_review.bat` | 정기 점검 실행(작업 스케줄러용) |
| `docs/DB_설계.md` | 저장소 설계: 이전 방식의 문제, DB 선택, 층·주제, 표 구조, 자료 생애, 정기 점검 |
| `run.bat` | 인덱스가 없으면 만들고 앱 실행 |

| `add_page.py` | 📚 자료 관리 화면(자료 추가 / 등록 자료 / 알림·정기 점검) |
| `doc_agent/` | 참고자료 타당성 평가 에이전트(`agent.py`), 기준(`criteria.json`), 등록·사용 중지·완전 삭제(`ingest.py`), 학기별 정기 점검(`periodic_review.py`), 자료 추가 때 평가 결과(`reports/`) |
| `index/legacy_backup/` | 저장소로 옮기기 전의 `chunks.json`·`embeddings.npy`·`registry.json`(백업) |
| `eval/run_eval.py` | 평가 실행(`run_eval.py v8`, `--full`은 문서 전체를 넣는 노트북형 기준선, `--ids=Q1,Q2`는 일부만). 결과는 `eval/results/` |
| `wee_case_analysis.html` | Wee 우수사례집 42건 주제 분석 결과 |
