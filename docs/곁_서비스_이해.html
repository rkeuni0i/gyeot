질문→질문 분석: 유형·주제·검색어·조각→유형별 확인 순서로 자료별 검색→근거 쪽 단 답변(스트리밍)→인용 검증·더 맞는 쪽 추천·사용 전 확인→답변 캐시

③ 판단은 사람이: AI는 자료를 평가·추천만 하고, 등록·교체·삭제는 상담교사가 승인한다.

3-1 쪽 글자 뽑기 · rag.page_texts()

PyMuPDF로 쪽마다 글자를 뽑고, 글자가 30자 미만인 쪽(그림·스캔)은 OCR 결과로 채웁니다. OCR 결과는 파일 이름이 아니라 파일 내용의 해시(SHA-256 앞 32자)로 data/ocr/에 저장해, 파일 이름을 바꿔도 다시 OCR하지 않습니다.

3-2 조각 나누기 · rag.doc_chunks(), split_text(size=900, overlap=150)

쪽 단위로 자르고, 한 쪽이 길면 900자씩 150자 겹치게 나눕니다. 조각 ID는 guide:p44-0처럼 자료:쪽-번호라서 답변의 쪽 근거와 바로 연결됩니다. 각 조각에는 장 이름(section)을 붙입니다. 가이드북은 목차 기준 구간표(SECTIONS), 학교 규정은 조문 제목, 매뉴얼은 목차에서 장 이름을 가져옵니다.

왜 쪽 단위인가? 상담교사가 원본에서 바로 찾을 수 있는 단위가 “쪽”이기 때문입니다. 150자 겹침은 문장이 조각 경계에서 잘려 뜻이 끊기는 것을 막습니다.

추가 자료(상담교사가 올린 자료)는 등록 때 고른 “쓰일 유형”과 “주제”로 붙습니다. 질문 주제와 자료 주제가 겹치면 검색 몫을 (3,1,5) → (5,2,9)로 늘립니다(ADDED_TOPIC_BUDGET). 복합 질문은 조각들의 유형별 순서를 merge_plans()로 합칩니다: 첫 유형의 순서를 지키고, 같은 자료는 몫이 큰 쪽을 씁니다. 자료가 늘어도 프롬프트가 무한정 커지지 않게 fit_budget()이 본 질문 검색의 최대 청크 합을 60으로 맞춥니다(1·2순위 자료 몫은 그대로, 나머지를 같은 비율로 줄이고 자료마다 2개는 남김. 학교 맞춤형은 89 → 60).

왜 자료별로 따로 검색하나? 한꺼번에 검색하면 216쪽 가이드북 조각이 상위를 다 차지해서 22쪽짜리 학교 규정이 아예 안 나왔습니다. 자료마다 몫을 나눠 뽑아 합치니 작은 자료도 항상 후보에 들어옵니다.

vec_rank = 코사인 순위                # 질문 임베딩 · 조각 임베딩

  • 필수 항목 검색: 위기면 “보호자 연계 거부 시 대체 지원”, 학교폭력이면 “전담조사관 배정” 같은 고정 검색어를 그 유형 1·2순위 자료에서 최대 3조각씩 더 찾습니다(사례 2 보완). 다문화·장애 학생이면 “이주배경학생 사안조사 통역”, “장애학생 특수교육 전문가 진술조력인” 묶음을 가이드북에서 찾습니다(과제 F).

4-5 인용 검증 · parse_citations(), check_citations()

  2. 뜻 유사도: 후보 줄만 한 번에 임베딩해 인용 쪽 조각들과 코사인. 0.70 미만이면 “근거 약함”.
  3. 구절 단위: 줄 전체는 맞아도 쉼표·“-고/-며/-거나”로 나눈 구절 중 핵심어가 인용 쪽에 하나도 없고 뜻 유사도도 0.66 미만이면 “근거 약함”.
  4. [일반 원칙] 혼합: [일반 원칙]과 쪽 번호를 함께 단 줄은 뜻 유사도 0.75 미만이면 “근거 약함”(더 엄격).
  5. 더 맞는 쪽 추천: 근거 약함 후보 줄마다 이번에 검색된 모든 쪽과 뜻을 비교해, 인용한 쪽보다 0.03 이상 가까운 쪽을 “더 맞는 쪽”으로 보여 줌. 단어 겹침이 낮은데 다른 쪽이 0.08 이상 더 가까우면, 인용 쪽 뜻 유사도가 0.70을 넘어도 근거 약함으로 남김.

4-6 스트리밍과 정지

stream_answer()는 stream=True로 LLM을 불러 글 조각을 하나씩 돌려줍니다. 화면(app.py)은 조각마다 box.markdown(text + " ▌")로 다시 그립니다. Streamlit은 버튼을 누르면 스크립트를 처음부터 다시 실행하는데, 그 순간 그리던 루프가 멈춥니다. 이 성질을 이용해 정지를 만들었습니다.

st.session_state.partial = {"question": q, "text": ""}   # 생성 시작 전에 기록
for piece in stream_answer(ctx):
    text += piece
    st.session_state.partial["text"] = text            # 조각마다 저장
    box.markdown(text + " ▌")                          # ← 정지를 누르면 여기서 중단
...
st.session_state.pop("partial")                        # 끝까지 쓰면 지움

# 다음 실행 맨 앞: partial이 남아 있으면 = 멈춘 것
if _partial: messages.append(... done + "⏹ 답변 생성을 멈췄습니다.")

정지 버튼 자체는 일반 Streamlit 버튼(key="stop_gen")이고, 작은 자바스크립트(STOP_JS)가 0.15초마다 입력창 보내기 버튼의 위치를 읽어 그 위에 겹쳐 놓습니다. 생성 중에는 보내기 버튼을 CSS로 숨깁니다.

파일 이름이 아니라 본문으로 비교합니다.

  1. 파일 바이트 해시가 같으면 즉시 “같은 자료”.
  2. 본문을 단어 4개 묶음(shingle, 숫자·연도 제외)으로 만들어 양방향 겹침을 계산: 새 자료 중 등록본과 겹치는 비율 a, 등록본 중 새 자료와 겹치는 비율 b.
  3. 판단: 겹침 0.30 이상(또는 제목이 0.6 이상 비슷하고 겹침 0.15 이상)이면 같은 자료의 판 후보 → 둘 다 0.85 이상이고 연도가 같으면 같은 자료, 연도가 더 최근이면 개정판, 더 오래됐으면 구판, 연도를 모르면 “많이 겹침”.

발행 연도와 그 출처 year_info(): 표지(1쪽) → 발행 정보(마지막 3쪽) → 본문 표현 → 등록 정보 → 파일 이름 → 제목 순으로 찾고, 어디서 읽었는지 화면에 함께 보여 줍니다(예: “표지 p.1: 2026년도 일부개정”). 2~3쪽은 “2023년에 개발한 ○○”처럼 다른 자료 얘기가 많아 표지로 보지 않습니다. 보완(2026-10-23): ① 표지의 “2024 TR-34” 같은 보고서 번호는 연도로 보지 않음 ② 표지에 네 자리 연도가 없으면 “연구보고 25-위센터02”의 두 자리 연도(2025)를 씀 ③ 발행 정보(마지막 쪽)는 부칙 개정 이력처럼 여러 해가 나열되면 가장 늦은 해(이산중 규정 2019 → 2026).

왜 4단어 묶음인가? 단어 하나로 비교하면 같은 분야 자료는 다 비슷하게 나옵니다. 4단어가 연속으로 같으면 같은 문장일 가능성이 높아 “같은 책의 다른 판”을 잘 구분합니다. 숫자·연도를 빼는 이유는 개정판에서 연도와 날짜만 바뀌는 경우가 많기 때문입니다. 실측: 가이드북 2025 ↔ 2026 겹침 83%/87% → 개정판.

6-3 AI 평가 12기준 · doc_agent/agent.py, criteria.json

평가는 세 단계로 나눠 LLM의 역할을 좁혔습니다.

  1. 자동 측정 measure(): 쪽 수, 쪽당 글자 수, 글자 없는 쪽 비율, 표지 연도, 발행 기관 후보, 지역 언급, 주제 키워드 수, 개인정보 패턴(전화번호 등) 수, 재배포 제한 문구, 기존 자료와의 제목 유사도·본문 표본 임베딩 최대 코사인.
  2. LLM 심사 judge(): 측정값 + 쪽 표본(약 26,000자)을 주고 기준마다 0/1/2점과 근거 쪽을 JSON으로 받음.
  3. 판정은 코드로 decide(): 가중 점수 = Σ(가중치×점수) / Σ(2×가중치). 필수 기준(중복·충돌, 추출 품질, 개인정보) 중 0점이 있으면 비추천, 55% 미만 비추천, 75% 이상이고 0점 기준이 없으면 추천, 나머지 조건부. 점수가 빠진 기준은 0점(확인 못 한 것은 좋게 보지 않음).

왜 판정을 LLM에게 맡기지 않았나? 같은 점수를 줘도 LLM은 그때그때 “추천/조건부”를 다르게 말할 수 있습니다. 점수는 LLM이, 규칙 적용은 코드가 하게 해 판정이 항상 같은 기준으로 나오고, 판정 이유를 문장으로 보여 줄 수 있습니다.

6-4 등록·교체·삭제 · doc_agent/ingest.py

  • add_document(): 인용 이름·제목·쓰일 유형·주제·층·적용 지역을 정해 등록하고 그 자료만 조각·임베딩(증분 인덱싱, 진행 막대). 적용 지역을 고르지 않으면 guess_region()이 추정(학교 층 → 학교, 평가 제안, 교육부 없이 ○○교육청만 → 그 시·도, 그 밖 → 전국). 기본 자료 자리가 비어 있으면 그 자리(base_slot)로 등록 가능.
  • replace_edition(): 개정판으로 교체. 인용 이름·확인 순서는 유지하고 이전 판 PDF·조각을 지움. 이전 판 삭제는 상담교사가 동의 체크를 해야만 진행. 선택지: 교체 / 이전 판 사용 중지 / 둘 다 유지.
  • delete_document(allow_base=…): 기본 자료는 확인 후에만 삭제.
  • caution_alerts(): 평가의 주의할 점과 OCR 여부는 참고 알림(답변 아래 접힌 목록), 0점 기준(이용 조건 등)은 주의 알림(답변 아래 경고 상자).

6-5 학기별 점검 · doc_agent/periodic_review.py

  • 앱이 열릴 때 start_background_if_due(): 마지막 점검 후 182일이 지났으면 백그라운드 스레드로 전체 재평가. review.lock 파일로 두 번 동시에 돌지 않게 함(3시간 지나면 무효).
  • 자료마다 다시 평가해 알림 생성: 비추천(긴급), 판정 하락, 기준이 새로 0점, 최신성 하락, 발행 3년 경과, 학교폭력예방법 시행일이 자료 발행 연도 이후(법 개정 확인 필요), 유의사항(정보). 같은 알림은 중복 생성하지 않음.
  • 점검 중이면 알림 아이콘에 파란 점 표시.

예상 질문과 답

ChatGPT나 Gemini에 PDF를 올려서 물어보면 되지 않나요?

실제로 같은 질문을 Gemini 노트북(문서 전체 투입)과 비교했습니다. 정답률은 비슷하거나 곁이 조금 높았지만, 차이는 근거를 쪽 단위로 확인할 수 있는지, 학교 규정과 지역 기관이 반영되는지, 자료를 학기마다 점검하는지입니다. 사례 2에서 노트북은 따돌림 피해 결석을 숙려제로 단정했는데, 곁은 출석 인정을 먼저 안내했습니다.

AI가 틀린 답을 하면 어떻게 하나요?

세 겹으로 막습니다. ① 자료에 있는 내용만 쓰게 하는 규칙, ② 문장마다 근거 쪽과 원본 쪽 이미지, ③ 근거와 맞지 않는 문장·구절을 자동으로 “근거 약함”으로 표시하고, 이번에 검색된 쪽 중 더 맞는 쪽을 추천. 다른 지역 자료·질문 주제 밖 자료·OCR 자료를 인용하면 따로 알립니다. 그리고 화면에 “최종 판단은 상담교사”라고 안내합니다.

왜 키워드 검색과 벡터 검색을 같이 썼나요?

법·절차 질문은 “48시간”, “제17조”처럼 정확한 단어가 중요해서 키워드 검색이 강하고, 상담 질문은 표현이 달라도 뜻이 같은 문장을 찾아야 해서 벡터 검색이 강합니다. 두 순위를 RRF로 합쳤습니다.

개인정보는 어떻게 보호하나요?

실제 학생 이름·학교·연락처 입력을 화면에서 막도록 안내하고, 자료 평가에서 개인정보 기준을 필수로 둬 실제 개인정보가 많은 자료는 비추천합니다. 대화는 이 컴퓨터에만 저장합니다. 2단계에서 자동 가림을 넣을 계획입니다.

다른 학교에서도 쓸 수 있나요?

학교 이름·정보·연계 기관은 설정값(SCHOOL_NAME, LOCAL_AGENCIES)이고, 학교 규정은 자료보관에서 그 학교 규정 PDF로 바꾸면 됩니다. 여러 학교가 함께 쓰려면 2단계의 PostgreSQL 전환과 로그인이 필요합니다.

답변 시간이 긴데 줄일 수 있나요?

답변 전 준비는 3초로 줄였고, 남은 시간은 대부분 답변 생성입니다. 스트리밍으로 첫 글자가 바로 보이게 했고, 자주 묻는 질문 캐시(같은 첫 질문은 1초 안)와 자료 수에 맞춘 검색 몫 조정(본 질문 합계 60청크)을 넣었습니다. 평균 20초 이하인지는 API 한도가 풀린 뒤 31문항 평가로 확인합니다.

Gemini 인증(ADC 또는 API 키)이 없으면 무엇을 할 수 없나요?

질문 답변(질문 분석·임베딩·답변 생성), 근거 약함의 뜻 비교, 자료 추가의 AI 평가와 임베딩, 개정판 교체·다시 평가·정기 점검, Gemini OCR, 품질 평가는 키가 필요합니다. 화면·이전 대화·자료 보기, 사용 중지·완전 삭제, 지역·연도 고치기, 알림 확인, 중복·판 확인, Windows OCR은 키 없이 됩니다.
